## 4. UDP 链路检查

### RFID 内部协议

- [ ] 固定 40 字节
- [ ] 发送方向：MineRailMonitor → RFID 分站
- [ ] 接收方向：RFID 分站 → MineRailMonitor
- [ ] 确认 RFID 监听端口可用
- [ ] 确认请求和响应的 CRC 与现场协议一致

### External Alarm 状态协议

- [ ] 固定 12 字节
- [ ] 发送方向：MineRailMonitor → 外部系统
- [ ] 接收方向：外部系统 → MineRailMonitor
- [ ] 状态帧 Byte4：`01` 正常、`02` 识别中、`03` 脱节报警
- [ ] 状态帧 Byte7 携带当前累计车厢数量
- [ ] 清除帧已验证帧头、模式、CRC、帧尾和基站地址
- [ ] External Alarm 发送失败不会改变 RFID 健康状态

## 5. 现场验收流程

### 正常

- [ ] 无车辆时收到 External Alarm 状态帧
- [ ] 确认 Byte4=`01`

### 识别

- [ ] 模拟或实际读取车辆 RFID
- [ ] 确认 Byte4=`02`
- [ ] 确认 Byte7 等于当前累计车厢数

### 报警

- [ ] 制造数量不足或超时场景
- [ ] 确认产生本地脱节报警记录
- [ ] 确认 Byte4=`03`
- [ ] 确认报警状态发送目标为对应站场配置

### 清除

- [ ] 外部系统发送合法 12 字节清除帧
- [ ] 确认地址匹配对应 Yard 和 RFID 基站
- [ ] 确认系统进入：`Clear → WaitForEmpty → Idle`
- [ ] 清除过程中不会直接跳过现有恢复流程

### 恢复

- [ ] 发送空 RFID 响应
- [ ] 确认 Passage 恢复为 `Idle`
- [ ] 确认 External Alarm Byte4=`01`
- [ ] 确认报警记录和 SQLite 历史记录仍完整

## 6. 常见问题

- **IP 配置错误**：确认 RFID 监听地址、External Alarm 目标地址和监听地址均为现场实际地址。
- **端口占用**：检查 RFID 监听端口和 External Alarm 监听端口是否被其他进程占用，且两者不能复用。
- **UDP 被防火墙拦截**：确认 Windows 防火墙及现场网络策略允许对应 UDP 入站和出站通信。
- **CRC 错误**：保留原始 HEX 报文，核对计算范围、算法及高低字节顺序。
- **地址匹配错误**：确认 External Alarm Byte2 与对应 RFID 基站地址一致，并确认 560、620 的 Yard 配置独立。
- **未进入报警**：确认已达到现有 Passage 报警条件，并且持久化成功后才进入外部状态报警发送。
- **未恢复正常**：确认外部清除帧合法，且后续已收到满足现有策略的空 RFID 响应。
